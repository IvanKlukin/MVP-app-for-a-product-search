# Архитектурные границы и ограничения MVP

В соответствии с техническим заданием на разработку MVP приложения (вариант 6), проект строго ограничен локальным набором функций без усложнения избыточной инфраструктурой.

## Границы реализации (Non-Goals)
В рамках текущей версии приложения осознанно **не реализовывались**:
- Внешний сервер, REST API и облачные базы данных (приложение функционирует 100% автономно).
- Регистрация, авторизация и система паролей для ролей пользователей.
- Работа с несколькими магазинами или несколькими этажами торгового комплекса.
- Геолокация покупателя, GPS и датчики движения.
- Алгоритмы построения оптимального маршрута обхода торгового зала (A*, Дейкстра).
- Учет складских остатков и ценников.
- Полнофункциональный графический редактор схемы магазина.
- Оплата, онлайн-корзина и интеграция с кассовыми терминалами.
- QR-коды и сканирование штрихкодов камерой.
- Нейронные сети и нечеткий поиск (Levenshtein distance).
- Push-уведомления и фоновые службы.

## Технические ограничения
1. **Поддерживаемая платформа**:
   - Минимальная версия SDK: `minSdkVersion 17` (Android 4.2).
   - Тестирование в реальном времени проведено на эмуляторе Android 14 (API 34, `x86_64`). Для физических устройств с Android 4.2 рекомендуется предварительная ручная валидация файлового менеджера.
2. **Формат импорта**:
   - Поддерживаются текстовые файлы и CSV простого формата `Товар;Раздел`.
   - Не поддерживаются сложные многоколоночные файлы Excel (`.xlsx`) и экранирование кавычек.
3. **Хранение схемы**:
   - Поддерживается одно текущее растровое изображение плана торгового зала во внутренней памяти. При выборе новой схемы старая перезаписывается.

## Направления будущего развития
- Добавление графа связей между отделами для расчета кратчайшего пешеходного маршрута.
- Сканирование ценников и штрихкодов камерой устройства.
- Синхронизация каталога товаров с корпоративной ERP-системой магазина через локальный Wi-Fi шлюз.
- Поддержка нескольких торговых залов и многоэтажных торговых центров.
